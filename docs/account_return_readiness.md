# 계좌 수익률 계산 전 데이터 검증 기준

## 현재 코드에서 확인된 제약

- `accounts.initial_capital`은 시작 현금으로 쓰이지만 해당 금액의 기준일이 별도 저장되지 않는다.
- `cash_flows`에는 입출금 날짜, 유형, 금액, 통화가 있다.
- `transactions`에는 매매 날짜, 수량, 가격, 수수료, 세금이 있지만 거래 당시 환율이나 실제 계좌통화 결제액은 없다.
- `dividends`에는 배당 날짜, 통화, 실수령액이 있다.
- `portfolio/performance.py`의 `total_roi`는 총손익을 현재 보유분 매수원가로 나눈 참고치다.
- 외화 거래의 과거 원가/실현손익을 최근 환율로 환산하는 한계가 있다.

## 단계별 구현

1. 계좌 시작일, 시작 현금, 시작 보유종목을 구분하고 기존 initial_capital 값은 자동 변환하지 않는다.
2. 기존 계좌의 시작일 누락, 보유분 중복 입력, 입출금 중복, 시세·과거 환율 누락을 읽기 전용으로 진단한다.
3. XIRR에는 시작 평가액, 외부 입출금, 종료 총자산만 사용한다. 매수·매도와 재투자 배당은 내부 이동이다. 해가 없거나 불안정하면 계산 불가로 표시한다.
4. TWR에는 외부 입출금 전후의 시점별 총자산 평가액이 필요하다. 가격과 환율 시계열을 확보하기 전에는 정확한 TWR을 표시하지 않는다.
5. 외화 거래는 당시 환율 또는 실제 계좌 기준통화 결제액을 저장하도록 확장한다. 과거 현재환율 환산값은 참고치로 구분한다.
6. 신규 컬럼은 nullable 마이그레이션으로 추가하고 운영 DB 적용 전 백업, 롤백, 별도 승인을 받는다.

## 회귀 테스트 필수 항목

- 시작 현금만 있는 계좌 / 기존 보유종목으로 시작한 계좌
- 입금-매수, 매도-출금, 배당 재투자 시 이중계산 방지
- 같은 날 복수 입출금, 시작금 0, 음수 현금, 수익률 해 없음
- 혼합통화, 과거 환율 없음, 시세 없음/오래됨
- 사용자 간 계좌 데이터 및 계산 원천 격리

데이터 검증 전에는 XIRR/TWR 수치를 새로 표시하지 않는다.
