# 계좌 시작 자산 확정 도입 조건 (운영 미적용)

## 현재 상태
- 초안 조회/저장, 모바일 입력, 확정 전 읽기 전용 검증 API는 구현됨.
- `confirmed`로 전환하는 API나 UI는 **없음**. 시작 자산은 현재 현금잔고, 포지션, 성과 계산에 합산되지 않음.
- 신규 테이블은 운영 DB에 적용하지 않음. `init_db()`는 연결 확인만 하고 자동 테이블 생성하지 않음.

## 확정 전 필수 조건
1. 운영 DB 백업·복구 절차 및 마이그레이션 적용에 대한 사용자 명시적 승인.
2. 저장된 스냅샷 상태가 `draft`이고 소유 계좌가 일치하며 기준 통화가 일치할 것.
3. 서버에서 최신 스냅샷과 거래·입출금·배당을 동일한 트랜잭션 안에서 다시 조회해 검증할 것. 조회 후 확정 사이에 다른 요청이 변경하지 못하도록 잠금/버전 검증 필요.
4. 시작일 이전 기록은 확정 차단. 시작일 당일 기록은 기준 시각(거래 전/후) 불명확하므로 별도 정합성 확인 필요.
5. 시작 보유수량이 이후 매매기록과 중복 입력되지 않았는지 확인. 공통 종목이 없다는 사실만으로 정합성이 증명되지는 않음.
6. 시작 현금잔고와 기존 `accounts.initial_capital`, 입출금·배당의 중복 반영 여부를 확인. 현재 현금잔고 산식 변경 금지.
7. 종목 평가금액이 스냅샷 통화로 입력됐는지 확인하고, 다른 통화 자산은 기준일 환율 및 환산 근거 확보. 현 시점 환율을 과거 환율로 사용하지 않음.
8. 확인할 수 없는 사항이 남으면 확정 차단 또는 검토 대기. 경고를 단순히 무시하는 '강제 확정' 버튼을 만들지 않음.
9. 확정 API는 멱등성·동시성·감사 기록 및 소유권 테스트를 통과한 뒤 도입. 확정 후 수정 정책 별도 수립.

## 수익률 계산과의 분리
- 확정은 역사적 시작 상태의 승인이지 XIRR/TWR 활성화가 아님.
- XIRR에는 시작/종료 평가액, 날짜가 정확한 외부 현금흐름이 필요함.
- TWR에는 외부 현금흐름 시점의 포트폴리오 평가액이 필요함.
- 기존 거래 기반 손익률을 계좌 전체 수익률로 명명하거나 자동 대체하지 않음.

## 테스트 계획
- 타 사용자 계좌 404, 미인증 401, 스냅샷 없음, 이미 확정됨, 통화 불일치.
- 시작일 이전/당일 거래·입출금·배당, 중복 보유종목, 날짜 누락.
- 동시 초안 수정과 확정 경쟁, 실패 시 트랜잭션 롤백, 중복 요청.
- 신규 테이블 없는 환경에서 기존 계좌 기능 정상, 신규 경로 오류 안내.
- 모바일 iOS Safari/Android Chrome에서 검증 메시지·키보드·입력값 확인.
